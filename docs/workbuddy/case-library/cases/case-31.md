# Case 31｜一个电话，三个AI专家，从零搭出道路救援系统原型

> **WorkBuddy 案例集 · 第 31 篇**
> 分类：网站与应用开发

---

## 一、场景描述

中午接到我哥一个电话，只说了一句："你看能不能搞个道路救援的 App？"没有需求文档、没有竞品分析、没有预算说明，甚至连"我要哪些功能"都没说清楚。这种项目涉及车主端、师傅端、管理后台，还要实时定位、智能派单、支付结算，按传统方式光写方案可能就要两三周。

但转念一想，WorkBuddy 的专家中心里有 100 多个领域专家，可以试试用流水线方式让三位专家串行协作：架构师出蓝图 → 开发工程师出施工图 → 原型工程师出效果图。每一步的输出都是下一步的输入。

最终，一个下午就完成了从一句话需求到架构方案、开发方案、可交互原型的全套交付，整个过程如果用传统方式可能需要 3-4 周。

## 二、想要完成的任务

用 WorkBuddy 专家中心的三位 AI 专家（软件架构师、高级开发工程师、快速原型工程师）流水线协作，从一句话需求出发，完成道路救援 App 的整体架构设计、完整开发方案和可交互产品原型。

## 三、使用的 Skill

| Skill / 能力 | 用途 | 来源 | 所需权限 |
|---|---|---|---|
| 专家能力（软件架构师） | 设计系统整体架构，交付可扩展架构设计方案文档 | WorkBuddy 专家市场 | WorkBuddy 账号 |
| 专家能力（高级开发工程师） | 制定开发计划和技术方案，交付包含数据库、API、里程碑的完整开发方案 | WorkBuddy 专家市场 | WorkBuddy 账号 |
| 专家能力（快速原型工程师） | 搭建可交互的产品原型，交付 HTML 交互原型页面 | WorkBuddy 专家市场 | WorkBuddy 账号 |
| 文件传递能力 | 把上一步专家产出的文档作为下一步专家的输入 | 内置能力 | 本地文件读写 |

## 四、前置条件

1. 已安装并登录 WorkBuddy 客户端
2. 在专家市场找到并激活"软件架构师""高级开发工程师""快速原型工程师"三位专家
3. 本机有可写入的目录用于保存架构文档、开发方案与 HTML 原型
4. 浏览器可正常打开 HTML 文件用于预览原型
5. 网络可用，可正常调用各专家能力

## 五、在 WorkBuddy 中的操作

### 步骤 1：选定三位专家，明确流水线策略
进入 WorkBuddy App 左侧边栏「专家」入口，按分类浏览或搜索关键词找到三位专家：软件架构师、高级开发工程师、快速原型工程师。每个专家都是专属对话窗口，上下文独立，可同时开多个并行沟通，也可以像本案例一样串行——上一步产出文件直接传给下一步。
**关键步骤**：在专家中心分别激活三位专家，明确"架构师出蓝图 → 开发工程师出施工图 → 原型工程师出效果图"的串行协作策略。

### 步骤 2：请架构师出蓝图
在专家中心找到「软件架构师」，进入专属对话窗口，输入需求。几分钟后，架构师交付一份完整的可扩展架构设计方案，文档包含 9 个章节：设计原则、架构总览、核心服务设计、技术选型、数据架构、非功能性设计、演进路线、风险应对、团队配置。
**关键步骤**：架构师给出四层架构（用户触点层/业务网关层/核心服务层/基础设施层）、智能派单引擎评分模型（score = 0.4×距离 + 0.3×技能匹配 + 0.2×评分 + 0.1×负载）、三种派单模式（系统派单/抢单/人工调度）、三阶段演进路线（0-6 个月模块化单体、6-18 个月微服务拆分、18 个月以上 SaaS 赋能）。

### 步骤 3：请开发工程师出施工图
回到专家中心，找到「高级开发工程师」，开一个新的对话窗口。把架构师刚才产出的文档直接传给他，让他根据架构设计产出开发方案。开发工程师交付的方案细节远超预期。
**关键步骤**：方案包含 7 大模块项目结构（通用模块、API 网关、用户、订单、派单、支付、位置、通知、管理后台、统一启动模块）、6 个模块共 11 张数据库表、三个端合计 40+ 个 RESTful 接口、6 个月 MVP 拆成 12 个 Sprint（每个 2 周）的里程碑计划，以及部署架构、服务器资源估算和质量保障策略。

### 步骤 4：请原型工程师出效果图
再次回到专家中心，找到「快速原型工程师」，进入对话。把架构文档和开发方案文档一起发给它，请它快速搭建产品原型。最终产出一个完整的可交互 HTML 原型，不是画线框图，也不是静态页面，而是可以直接在浏览器里操作的页面。
**关键步骤**：原型覆盖三端功能——车主端（选故障类型、地图定位、填写描述、费用预估、支付、实时追踪）、师傅端（新订单推送、接单、当前订单管理、收入统计）、管理后台（数据概览、订单管理、智能调度、师傅管理、结算管理），采用暗色紧急主题（深色背景配橙色强调色），浏览器直接打开即可。

### 步骤 5：串联三步输出，对齐认知
三个专家各自在领域深耕，每一步的输出自然成为下一步的输入。架构师解决"怎么设计"，开发工程师解决"怎么开发"，原型工程师解决"长什么样"。文件传递是关键——把上一步产出传给下一步，信息不丢失、不扭曲，流水线式协作才能跑通。
**关键步骤**：以可交互原型作为对齐认知的工具，让产品、开发、设计看到同一个东西，比只靠口头沟通更有效。

## 六、提示词或任务指令

| 步骤 | 指令 | 作用 |
|---|---|---|
| 1 | `我们正在开发道路救援app系统，需要整体架构设计和长期发展规划，请软件架构师帮我们设计可扩展的系统架构。` | 触发软件架构师输出完整可扩展架构设计方案 |
| 2 | （把架构师产出的文档传给开发工程师）`根据架构设计产出开发方案` | 触发高级开发工程师输出项目结构、数据库表、API、Sprint 计划 |
| 3 | （把架构文档和开发方案一起传给原型工程师）`快速搭建产品原型` | 触发快速原型工程师输出三端可交互 HTML 原型 |

## 七、在 WorkBuddy 中的效果

### 交付物
1. 一份完整的可扩展架构设计方案文档（9 个章节，含四层架构、智能派单引擎、三阶段演进路线）
2. 一份完整开发方案（7 大模块项目结构、11 张数据库表、40+ RESTful 接口、12 个 Sprint 里程碑、部署与质量保障）
3. 一套可交互 HTML 产品原型（车主端、师傅端、管理后台三端覆盖，暗色紧急主题，浏览器直接打开可用）

- [ ] 架构师交付完整架构设计方案，含 9 个章节、四层架构、智能派单引擎评分模型、三阶段演进路线

- [ ] 原型工程师基于架构文档与开发方案交付可交互 HTML 原型，覆盖车主端、师傅端、管理后台三端
- [ ] 原型可在浏览器中直接打开操作，采用暗色紧急主题
- [ ] 三步产出的文档通过文件传递形成流水线，信息无丢失
- [ ] 整个流程在一个下午内完成，对比传统方式节省至少 3 周时间
