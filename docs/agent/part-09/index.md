# Part 9 / 前沿 Agent 能力

了解研究型、计算机操作、编码和后台运行等前沿能力，并把它们放回工程边界中评估。

## 本部分章节

| 章节 | 本章关注点 |
| --- | --- |
| [第 27 章：Deep Research](./chapter-27-deep-research) | 把开放问题拆成检索、核验、综合和引用的研究流水线。 |
| [第 28 章：Computer Use](./chapter-28-computer-use) | 让 Agent 通过屏幕、鼠标和键盘完成软件操作，同时控制误操作风险。 |
| [第 29 章：Agentic Coding](./chapter-29-agentic-coding) | 把代码理解、修改、运行、测试和审查组织为连续工程闭环。 |
| [第 30 章：Background Agents](./chapter-30-background-agents) | 处理异步、长时间运行和用户离线期间仍需推进的任务。 |
| [第 31 章：分层模型策略](./chapter-31-model-routing) | 根据任务难度、延迟、成本和风险选择不同模型或运行配置。 |
| [第 32 章：OpenClaw 时代](./chapter-32-openclaw-era) | 从开放生态和长时间运行的视角，讨论 Agent 能力组合与平台边界。 |
| [第 33 章：Building on the Harness — Kocoro](./chapter-33-harness-kocoro) | 从 Harness 视角理解运行时、工具、状态和用户交互如何共同支撑 Agent。 |

## 本部分产出

完成本 Part 后，你应该能：

- 用自己的话解释本部分的关键模式，而不是只记住名词。
- 为一个真实任务画出输入、状态、动作、反馈和验收的边界。
- 说明该模式的适用条件、主要风险以及不适用时的替代方案。

## 建议学习方式

先读本页了解知识地图，再按章节顺序完成练习。每章都保留一份任务卡和一份验收记录，最后把它们合并成一个可复用的 Agent 设计说明。
