# 第 15 章：Swarm 模式

理解多个相近角色如何围绕共享目标协作，以及共享状态的风险。

## 本章要解决什么

角色数量、共享记忆和协调消息如何保持在可控范围内？

本章不把某个框架的 API 当作结论，而是先明确任务边界、运行状态和验收证据，再决定实现方式。这样同一套方法才能迁移到 Codex、WorkBuddy 或其他 Agent 运行环境。

## 核心概念

- **目标与边界**：明确 Agent 要完成的结果、允许的操作和不能触碰的范围。
- **状态与证据**：记录当前进度、工具返回值和人工验收依据，避免只凭最终文字判断成功。
- **反馈与停止**：为每一步设置可观察反馈，并定义成功、失败、重试和停止条件。

## 建议练习

设计一个小型 Swarm，并限制角色数、交互轮次和退出条件。

建议把练习记录成一张任务卡：

| 项目 | 内容 |
| --- | --- |
| 任务目标 | 写出可验收的结果，而不是泛泛地“帮我处理” |
| 可用上下文 | 列出规则、资料、历史状态和限制 |
| 可用动作 | 只开放完成任务必需的工具 |
| 验收证据 | 指定谁在什么位置检查什么结果 |
| 失败回退 | 规定无法继续时如何停下并交接 |
