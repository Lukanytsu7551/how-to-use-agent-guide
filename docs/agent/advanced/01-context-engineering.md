# 01 / 上下文工程

上下文不是越多越好，而是要让 Agent 在当前步骤拿到**相关、准确、可执行**的信息。一个可维护的上下文通常包括系统规则、任务目标、当前状态、工具记录、必要历史和外部资料。

## 先分层，再压缩

| 层 | 内容 | 处理方式 |
| --- | --- | --- |
| 规则层 | 权限、格式、不可做的事 | 长期稳定，优先保留 |
| 任务层 | 当前目标、输入和验收 | 每次任务重新确认 |
| 状态层 | 已完成动作、待处理事项 | 随运行更新 |
| 资料层 | 文件、检索结果、工具返回 | 按需加载，标注来源 |

## 检查清单

- 当前步骤需要哪些事实？
- 哪些历史已经失效或重复？
- 工具返回值是否经过整理？
- Agent 是否知道什么时候应该停止？
